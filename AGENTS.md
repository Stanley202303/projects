# Project Rules

## Algorithm Selection

Standing rule for this project: always prefer classic, battle-proven algorithms and numerical methods.

Choose approaches that are:
- simple
- easy to explain
- easy to troubleshoot
- easy to validate
- easy to maintain

Do not use fancy, cutting-edge, or state-of-the-art methods unless explicitly requested.

This rule applies to:
- programming and implementation algorithms
- mathematical methods
- numerical methods
- engineering and physics methods

## UNIX Philosophy

Standing rule for this project: prefer well-defined, single-purpose applications.

Prefer applications that produce text streams as output, unless the application is specifically a GUI application.

The rationale is that we want our applications to be native to CLI agents.

## Python Coding Style

Standing rule for this project: prefer Pythonic coding style.

We accept a moderate level of design-pattern usage, but we do not want to abuse design patterns.

Coding style should always focus on readability.

Avoid scattering logic across multiple locations when it can be kept coherent in one place.

Be pedantic about naming conventions.
